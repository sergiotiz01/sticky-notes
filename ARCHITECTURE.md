# Architecture

The board is a React + TypeScript SPA with a single source of truth: an array of notes in a `useReducer` store. Each note is a plain object (`id`, geometry, text, colour, `zIndex`). User actions become typed reducer actions (`add`, `patch`, `remove`, `bringToFront`). Persistence is a side effect of that store — `localStorage` is read when the provider initialises and written after each state change — so UI components never talk to storage directly.

Pointer interaction is implemented without a drag-and-drop library. A small `usePointerSession` hook captures the pointer, listens on `window` for move/up/cancel (so Chrome and Firefox stay consistent when the cursor leaves the original target), and reports a delta from the original `pointerdown`. The board owns “create” sessions: dragging on empty canvas rubber-bands a rectangle and commits a new note on release. Each note owns “move” (header) and “resize” (edge/corner handles) sessions, keeping live geometry in local state and writing back to the store only on `pointerup`. Delete is a hit-test: during a move, the note’s rectangle is compared with the trash zone’s board-relative box; overlap highlights both, and release over the zone dispatches `remove`.

This split keeps drag frames cheap (no full-store update per mouse move), keeps typing and dragging from fighting (header vs body), and makes z-order a data concern (`bringToFront` assigns `maxZ + 1`). The UI is a few presentational components (`Board`, `Note`, `Toolbar`, `TrashZone`) plus geometry helpers for clamping and resize math, which is the surface we would walk through in a code review.
